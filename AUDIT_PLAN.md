# План аудита корпуса Maritime Docs

**Статус:** частично начат. Первичный рекурсивный снимок дерева создан в FILE_INVENTORY.csv для commit 09964febbfa6bae980f40da05174d98077c32034 (283 файла в снимке, до добавления самого CSV). Сопоставление PDF/TXT, идентификация документов, контроль OCR и внешняя проверка актуальности ещё не завершены. Это не отчёт о завершённом аудите.  
**Цель:** установить состав файлов, качество извлечения текста, представленные документы и редакции, а также пробелы, требующие внешней проверки.

## Важное различие
Нельзя доказать абсолютную полноту набора всех морских нормативных документов без заданной области. Аудит должен фиксировать типы грузов, операции, типы судов, юрисдикцию и дату. Итог — покрытие в заданных пределах, а не универсальная гарантия полноты.

## Этап 1. Инвентаризация файлов
- [ ] Получить полный рекурсивный список файлов целевой ветки и записать дату, ветку и commit SHA.
- [ ] Подсчитать файлы по расширениям и папкам; выявить файлы без расширения, технические имена и неожиданные форматы.
- [ ] Сопоставить исходные PDF/документы и текстовые извлечения.
- [ ] Найти PDF без соответствующего TXT, TXT без очевидного исходника и документы, разбитые на части.
- [ ] Сравнить содержимое/хеши вероятных дубликатов; не удалять автоматически, так как это могут быть разные редакции.

Результат: реестр всех файлов со статусом пары исходник/текст и списком аномалий.

## Этап 2. Идентификация документов
Для каждого документа установить, если это возможно: каноническое название, обозначение, год/редакцию/поправки, издателя, тип источника, область применения, тематические теги, связанные PDF/TXT, дубликаты и официальный URL.

Файлы с техническими именами нельзя классифицировать по имени. До проверки титульной страницы и содержания отмечать их как неидентифицированные.

## Этап 3. Контроль качества извлечения
- [ ] Сверить число страниц PDF с маркерами страниц OCR.
- [ ] Выявить пустые/повторные страницы, обрывы текста, испорченные таблицы, формулы, символы и единицы.
- [ ] Сопоставить с PDF ключевые разделы, таблицы и приложения.
- [ ] Обновить замечания в texts/extraction_report.txt только после фактической проверки.
- [ ] Для требований безопасности не считать OCR подтверждённым без сверки соответствующих положений с оригиналом.

Статусы: проверен в указанном объёме; частично проверен; OCR требует проверки; не прочитан; не идентифицирован. Не ставить статус «проверен» без указания объёма.

## Этап 4. Анализ пробелов по темам
Для каждой области (генеральные, навалочные, наливные, лесные, опасные, продовольственные грузы, пассажирские перевозки и другие заданные темы) создать матрицу:

| Тема/операция | Потенциально применимые источники | Есть в корпусе | Редакция установлена | OCR/оригинал проверен | Внешняя проверка | Итог |
|---|---|---|---|---|---|---|

Проверять не только тематические РД/ГОСТ, но и применимые конвенции, кодексы, поправки, резолюции, руководства и национальные требования. Не включать источник в обязательный список без проверки применимости.

Для каждого пробела выяснить: отсутствует ли документ; есть ли только старая редакция; существуют ли поправки/новый выпуск; соответствует ли локальная копия официальной; применим ли документ на нужную дату.

## Этап 5. Внешняя проверка
Искать прежде всего на официальных сайтах IMO, государственных правовых порталах, у компетентных регуляторов и организаций-издателей. Для каждого источника фиксировать URL, название, редакцию/дату, дату проверки и что именно подтверждено.

Сниппет, блог или случайная копия не подтверждают действующий статус. Если официальный источник недоступен, оставить вопрос незакрытым.

## Этап 6. Тестирование ответов агента
Подготовить тесты на: поиск пункта; полный перечень требований из одного документа; сопоставление документов; поиск недостающих документов; проверку редакции; отсутствие ответа в корпусе; исключение/отрицание; таблицу или приложение в PDF.

Оценивать:
1. источник существует и был открыт;
2. цитата и смысл соответствуют тексту;
3. пункт и страница верны;
4. условия, исключения и отрицания сохранены;
5. пропуски релевантных положений объяснены;
6. актуальность и применимость не заявлены без доказательств;
7. ограничения поиска раскрыты честно.

## Этап 7. Результаты аудита
После выполнения этапов подготовить:
1. FILE_INVENTORY.csv — реестр файлов;
2. DOCUMENT_REGISTER.csv — канонический реестр документов и редакций;
3. GAP_ANALYSIS.md — отсутствующие и сомнительные источники по темам;
4. обновлённый texts/extraction_report.txt — состояние OCR;
5. AUDIT_REPORT.md — дата, commit SHA, метод, ограничения, результаты и незакрытые вопросы.

Не заполнять поля догадками и не публиковать аудит как завершённый, пока соответствующие этапы реально не выполнены.
